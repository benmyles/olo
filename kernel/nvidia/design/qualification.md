# Qualification and recovery contract

## Runs performed without a GPU

The release tree is verified/. tests/run-halt-test.py baseline verified builds five NVIDIA function bodies verbatim with fake clock, thread deadline and register callbacks. The code includes both NVIDIA timeout functions, the local check, the GA102 poll, and the GH100 caller. tests/run-stage-test.py verified exercises the production standby/GCOFF control flow with named mock stage failures. tests/run-channel-test.py verified links the built display and push-buffer leaf objects and supplies RAM-backed registers, notifier and fake clock.

The KVM guest carries the final nvidia.ko, the synthetic PM device and a separate refcount fixture. The latter compiles the driver reference and draining functions with mock RM resources, real Linux semaphores, completion and two kernel threads. An ID and UUID put must work after unpublication. An ordinary get must fail. The final KMS put runs with the mock stack allocator returning ENOMEM. Guest boot has no PCI passthrough, display, disk or network device. The runner is Olo's tools/dev/kvm-guest with the scratch directory redirected to nvfork. The result is tests/guest-final.txt. The release NVIDIA module returns ENODEV on a machine without NVIDIA hardware.

## Healthy card, during a separate maintenance window

1. Use a spare board of the same family first. Keep an Intel-driven boot, a known-good boot choice with matching RPM Fusion kernel modules, firmware and user libraries, saved work, local console and an out-of-band restart available. Record driver build IDs, kernel, GSP firmware, topology including HDA, and the display/PM configuration. Keep the stock package available. The current stuck boot is outside this procedure.
2. Boot the prevention subset first. Confirm the actual loaded build IDs against the stage manifest, and confirm the Intel primary, NVIDIA compute result, and available connector roles. Save a small data set and its expected checksum while the system is healthy. Hold enough free memory to exercise a normal transition. Capture timestamped suspend and resume return values and actual GCOFF selection. Run a normal idle/wake/verified-compute cycle, then repeat. A power-state label alone is insufficient.
3. On the build including the test patch, read the intended GPU's minor from its NVIDIA information entry. Write that minor once to /sys/module/nvidia/parameters/test_defer_gcoff_minor as root. Mode is 0600, and the disarmed value is -1. It applies to the first matching dynamic GSP GCOFF selection. An ordinary GC6 cycle does not consume it. On a healthy SR allocation, the callback must return -EAGAIN before any engine unload. Observe the one-shot message, the parameter returning to -1, no persistent runtime error, balanced PM notifications, a valid immediate compute checksum and a later successful ordinary cycle. Disarm with -1 if the intended branch is never selected. Do not manufacture system-wide memory exhaustion.
4. Qualify normal client ownership separately. Close, reopen and transfer DRM ownership with fbdev both on and off on separate boots. Test an unplugged render-only configuration and an external display actually driven by the GPU. Exercise a dma-buf client, UVM/CUDA, video and vblank/hotplug across ordinary teardown. Close clients cooperatively first. Record worker completion, balanced owner counts and fence status. Keep a known external holder alive in the software fixture to verify removal remains pending safely. A real driver must refuse a maintenance transaction before unbinding if it cannot revoke that owner.
5. The virtual tests name the post-unload, engine, halt, idle, notifier, frozen-GET and resume cases. For a genuine late hardware failure, a release needs a vendor-backed way to fence the device and retain old mappings until the fence is established. On a separate qualification board capture GSP send, mailbox, HALTED samples and elapsed times, last successful engine, reset entry/result, pending DMA and outstanding owners. Hardware acceptance includes a bounded operator outcome, all old completions signalled with errors, DMA isolation independently verified, a fresh driver generation and an end-to-end checksum with fresh allocations. A successful PCI configuration read, a reset return of zero, or a runtime_status display is insufficient.
6. If any operation remains in the kernel, record the phase and leave ownership with that operation. Do not start a concurrent unload, unbind or second reset. Boot the known-good set after saving the rest of the session, with a full power cycle if a warm restart fails. A bus reset affects the HDA sibling and any other device below the bridge and requires the full downstream topology to be quiesced.

## Required before claiming bounded late recovery

Keep per-device admission and per-binding lifetime independent. Existing open files, VMAs, dma-buf exporters/importers, UVM registrations, fence waiters, RM work, IRQs and KMS owners must each have a revocation or a documented final-put path. Block new hardware access before cancellation. Revoke BAR mappings and fault them to an error. Signal waiters with a device-lost error under the corresponding lock. Pins and DMA backing must survive until producers can no longer DMA. Disconnect callbacks, synchronize interrupts, drain per-device workers and retain their state until the last invocation exits. Avoid waiting with a lock needed by a put or worker.

A vendor-qualified quiesce sequence must cover the display engines and GSP as well as PCI bus mastering, outstanding transactions and the IOMMU domain. A successful fence permits host-only resource teardown. If fence/reset fails, retain the pinned generation and return a bounded failure from the *maintenance request*. An old kernel module may remain pinned. Linux's void PCI remove callback cannot implement a busy veto. A full refactor needs references that can outlive physical unplug and cannot access the next generation. Inability to establish these preconditions is an explicit restart-required result. Even a correct driver cannot guarantee replacement of code still referenced by arbitrary external clients in bounded wall time.
