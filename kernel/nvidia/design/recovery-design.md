# Recovery design and release boundary

## Failure transitions

| Last trustworthy point | Disposition | Work in the series |
|---|---|---|
| Insufficient runtime-suspend stack or FB reservation, before engine transition | The adapter is operational. Defer, balance any reservation or power reference, permit later Linux retry. | 0003 handles suspend stack allocation. The tag already retries the pre-engine GCOFF reservation OOM when GC6 fallback is unavailable. |
| Mandatory SR metadata allocation or spent thread deadline while preparing GCOFF | Return temporary backing, clear the in-PM path and depth, restore the captured interrupt mode and balance the suspend notification. | 0003. The observed card reached a later stage. A terminal failure of this allocation would have taken this earlier exit. |
| An engine pre-unload hook has run, engine unload returned an error, or complete engine unload preceded a GSP error | Keep a per-probe terminal admission state. Avoid an automatic reverse call. A full reverse needs a ledger of completed engine hooks, valid retained backing and proof of firmware state. | 0004 sets rtd3_restart_required and the existing GSP fatal-RPC gate on a non-retryable GSP transition error returned by RmGcxPowerManagement. Opens fail and the existing Linux lost-device checks cover poll/ioctl/mmap/ISR paths. A control-fd RPC is checked again in the GSP send path. The proc power report can report the error from host memory. Already mapped BARs and already running jobs need explicit revocation. |
| GSP suspend sent, mailbox fails, or CPUCTL has not halted by the new deadline | Firmware command is fire-and-forget. Hardware might still be using DMA targets. Quarantine and retain old resources until independently fenced. | 0001, 0004 and 0005 bound and preserve handshake errors. The series still has the stock error-side FBSR frees and later destruction of the GSP SR descriptors. This is a release blocker for late hardware injection or guaranteed cold recovery. |
| PCI presence/firewall or firmware resume fails | Stop before later BAR accesses. Do not signal successful resume or re-enable interrupts. Keep terminal admission closed. | 0004 stops the formerly unconditional next resume step and propagates the formerly ignored gpuResumeFromStandby result for runtime GSP. 0005 gives PCI presence its own budget. Dependencies and late lifetimes still require a working reset protocol. |
| Fresh generation after independently verified reset | Prove config/BAR access, firmware boot, engine load and new mappings. Then reconcile Linux PM and open admissions. | Design requirement. No on-card reset or reprobe result is available. |

Prepare/commit boundaries must include engine-internal partial writes. gpuStateUnload walks all engines and intentionally ignores several returned errors after recording them (gpu.c 3894–3965). Its depth enum is too coarse to replay an inverse sequence. Generic pre-RM lock errors, the Linux devfreq callbacks and some platform-specific returns are outside the new terminal-state assignment. The draft does not assert that every RM or platform failure is transactional.

The SR region sizes arrive after firmware initialization (kernel_gsp.c 5794 and the per-family srRegionsInfo population). The radix descriptor contains page tables plus the firmware save payload. The tag tries 2 MiB pages, then 4 KiB for OOM, and separately creates and maps the metadata. A cache would need to allocate after layout discovery, remember the firmware, geometry and DMA mapping generation, rewrite firmware-modified metadata on each cycle, initialize/scrub reusable storage under the firmware contract, and invalidate after a changed layout, reset, detach or failed restore. Never expose stale contents or DMA addresses across generations. Separate the SR cache from FBSR's variable used-VRAM reservation, copies of allocation nodes, other engine allocations, and the optional Linux altstack. Pinning the peak framebuffer save for the lifetime of a laptop would itself consume memory during pressure. The draft reserves only the teardown stacks on acquisition/probe. A release decision on permanent SR caching needs measurements of retained bytes and verified metadata renewal.

## Removal

The Linux PCI core calls pm_runtime_get_sync, a PM barrier and then the driver's void remove callback. The resume request can fail, and PCI still proceeds into remove. nv_pci_remove_helper stops open_q, invokes the modeset removal callback, unpublishes the GPU, notifies RM, and handles remaining clients. Patches 0002, 0006 and 0007 remove the allocation dependency on this path, preserve the identity of each modeset lease, and make remaining keyed releases possible. nv_linux_wait_for_users_locked drops both locks and wakes at the real final put. A process retaining an fd can still postpone that completion indefinitely.

On the far side of the drain, rm_check_for_gpu_surprise_removal can read BAR0 and enter crash diagnostics. nv_stop_device takes a fine-grained power reference and may run nv_shutdown_adapter. rm_cleanup_dynamic_power_management can call nv_indicate_not_idle, whose PCI shutdown wrapper discards a resume error. nv_shutdown_adapter calls rm_disable_adapter, stops IRQ work and removes interrupt handlers, then calls rm_shutdown_adapter. RmDisableAdapter may run gpuStateUnload for the initialized engines. RmShutdownAdapter destroys PM/watchdog state, RM clients, engines and register mappings, and gpuStateDestroy can call kgspUnloadRm again. The GSP fatal gate cuts new RPC sends short but cannot quiesce an already issued DMA transaction or make an outstanding callback stop. Merely skipping these functions would also skip host cleanup. Splitting the hardware quiesce and host destructors is necessary.

An independent per-binding object should anchor all surviving old references. Admission, ref acquisition and removal must be serialized at the point where a reference becomes externally visible. Revoke mappings and fence access. Keep old-generation completion/error delivery working after the public device ID is gone. Carry an explicit fence/reset result into each hardware-facing destructor. In a verified-quiescent generation, omit register programming, console restoration, firmware RPCs, and duplicate unload operations while still unregistering IRQs, cancelling work, freeing the RM hierarchy, detaching DMA mappings and releasing PCI regions. On failure to prove quiescence, retain backing and refuse reassignment. Do not let a new probe reuse the old resources. The KMS lock and RM GPU lock need an explicit ordering protocol, especially if scheduling recovery from the PM callback.

## Linux PM error semantics

Use -EAGAIN or -EBUSY for a rejected suspend only after establishing that the device still works. The core can reschedule an autosuspend depending on usage and expiration. After an ambiguous destructive transition, return a fatal error and preserve that information. Linux 7.2.15 runtime.c 472 records the error, and later ordinary resume observes it. A recovery worker operating *after* the callback may serialize/disable runtime PM, establish a genuinely active device, call pm_runtime_set_active, check the result, then balance PM enables and usage references. __pm_runtime_set_status at 1313 permits this when PM is disabled or an error is latched. Parent/supplier state can still prevent it. A setter called inside the failing callback precedes the PM core's error recording. A new probe on the same pci_dev also needs correct PM initialization. Qualification includes the device-link parent counts, usage references and normal cycles afterward.

Where FLR cannot recover the device, a bus reset needs consent and quiescence for every downstream function, including HDA. The saved reset_method value was “flr bus”. It describes available methods. A firmware or board that cannot be restored may still require a platform power cycle.
