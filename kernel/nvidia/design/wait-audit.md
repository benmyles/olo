# Display, RM and Linux waits on 615.71.09

Line numbers below name the pristine tag. Times are elapsed-clock checks once the thread runs again. A bound on polling does not imply a bound on a register access, firmware control call, allocator, external fence, lock or worker join inside an iteration. The NVKMS timeout helper multiplies intervals by 100 for emulation other than DFPGA. The affected machine is silicon.

## RM polling before and after suspend

* kgspUnloadRm issues GMCAPI_CMD_GSP_SUSPEND before the suspend-mailbox and final-halt checks. Patch 0005 gives only the RTD3 suspend command one local 1 s TX reservation across all fragments. The default send path previously had a nominal 1 s timeout per element that still consulted the calling thread. Encrypted queues are classified from the command before encryption.
* With bProcessRpcs=true, kgspWaitForProcessorSuspend_TU102 calls gpuRpcConditionWait. The outer poll already uses BYPASS_THREAD_STATE (kernel_gsp.c 3360), normally 1.5 times defaultus. The inner _kgspRpcDrainEvents (2048) can keep receiving unrelated events. Patch 0005 returns to the outer checker after 32 events, preserving queue order and the original absolute deadline. The interrupt drain keeps its existing behavior. One event handler can still block. The unprocessed-RPC variant uses gpuTimeoutCondWait and is a different path.
* Blackwell PCI presence used the default parent-thread deadline (kernel_bif.c 1895). The draft gives it a local timer in RTD3. BAR firewall (kernel_bif_gb202.c 341) and the FSP secure-boot handshake (kern_fsp_gb202.c 87) already bypass the thread. The latter uses at least 5 s. The GH100 GSP boot HAL dispatches to FSP on this family. Generic queue linking (message_queue_cpu.c 369) and several bootstrap/engine waits still consult the parent budget on silicon. A blanket thread timeout reset would conceal a genuinely slow call and multiply per-engine worst cases.
* gpuStateUnload_IMPL (gpu.c 3818) destructs the event import and stops RUSD before it can return a pre-unload error. It visits engines in descriptor order, records failures and deliberately tolerates some. NV_PM_DEPTH_SR_META does not prove that zero engines changed state. The ordinary destructor makes another GSP unload request (gpu.c 4170). A hard deadline around these call sites cannot interrupt an arbitrary blocking callee.
