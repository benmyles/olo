Use an opt-in versioned source package from Olo's signed release or a content-addressed cache populated ahead of the kernel installation. The full upstream tree is needed for changes under src/nvidia and src/nvidia-modeset. The Fedora kmod source archive supplies kernel-open and two prelinked cores. Reuse the exact open-flavor distro prep hunk. The other two hunks in set_driver_defaults.patch target the closed flavor. Do not apply them to public open source by analogy.

The recipe pins tag object d2a24f90e843359450ab313a286f43a88d95c6ce, commit 61dcc93722ecb418bb5f2e00923f05b4b8051dd1, tree 9199a9f620b76343c35c207354ffcb3d1570053d, SHA-256 29c36a0a46b91fd17f96f977e046f303317cd6eedb5cbbefdcf0c95cfe7a0f38 for the uncompressed git archive, and the SHA-256 of every patch. GitHub reported unknown_key for the release tag's SSH signature at the time of this check. The recipe verifies content identity. A production packager must authenticate the upstream signing key independently or distribute a separately reviewed, Olo-signed source manifest. The RPM-installed source RPM here has valid payload/header digests and no independent OpenPGP signature, so use the signed containing RPM/repository as its distribution trust root.

The existing olo-kmod code embeds a small module's source, builds against /lib/modules/RELEASE/build, installs one .ko under extra/olo and offers to load it. For this driver, reuse the kernel selection, status and cleanup conventions. Treat the five .ko files as a single build generation. A suitable cache key includes kernel release and kernel-devel configuration, NVIDIA user-space/firmware release, architecture, distro prep revision, source and patch digests, compiler settings and signer. Preserve NVIDIA's version strings for user-space compatibility. Record build IDs and hashes per module and the Olo patchset identity separately.

Build unprivileged off the graphical path with a cancellable status view. Build when a new kernel-devel or NVIDIA package transaction is staged and before the target kernel's initramfs is finalized or the driver autoloads. An early first boot can use a complete, matching stock set when the patched build is unavailable. A graphical service that finishes later queues a candidate for the next boot. Kernel, firmware and user libraries promote together. A previous kernel boot alone cannot roll back newly installed, incompatible NVIDIA libraries. Keep a complete rollback generation.

Stage signed modules under an immutable generation outside the scanned hierarchy. Strip if required, sign the final uncompressed .ko with the kernel's scripts/sign-file and a trusted MOK/akmods key, then compress if desired. Keep signing keys in their existing privileged signing service. Treat a missing enrolled key or a failed signature as a promotion failure. Here the supplied evidence reports Secure Boot off. Build outputs in this review are unsigned.

A root packaging transaction publishes the complete set under /lib/modules/RELEASE/updates/olo, with stock under extra/nvidia. Serialize staging, directory replacement, depmod and early-boot artifact generation against akmods and auto-loading, ideally during an offline update. Verify resolution and dependencies of all five names in the staged root. A local depmod search/override can change precedence. A rebuild/patch/sign/compatibility failure disables the old override for that release before rebuilding the index and any relevant initramfs, verifies all five stock paths, and records the failure. Preserve a bootable previous generation if activation fails. Never partially replace running modules.

RPM Fusion's installed /usr/lib/dracut/dracut.conf.d/99-nvidia-dracut.conf requests omission of nvidia, nvidia-drm, nvidia-modeset and nvidia-uvm. It does not list peermem. The boot image here is mode 0600, and its contents were not inspected. In a packaging transaction list actual target initramfs/UKI contents, including modules and modprobe configuration, before selecting the action. If any old module is present, rebuild and verify the boot artifact, re-sign the UKI as applicable, and promote it with the module generation. An already loaded module cannot be selected by running depmod again.

Doctor should show the running build independently from the next-boot build. Read the loaded module's GNU build-ID note, on-disk module path and ELF note, the manifest, and cached PM failure state. Distinguish stock, Olo, mixed, unloaded and unknown. Display a next-boot candidate and the last build/sign error. The srcversion value and the NVIDIA version string alone are insufficient. Core-only changes in this investigation produced different bytes with the same srcversion. These metadata reads can be made without NVML or opening a GPU device.

The compiler settings in /var/cache/akmods/nvidia/.last.log include -O -j16 V=1 VERBOSE=1, KERNEL_UNAME, SYSSRC, IGNORE_CC_MISMATCH=1, IGNORE_XEN_PRESENCE=1 and IGNORE_PREEMPT_RT_PRESENCE=1. Both baseline and patched measurements use these switches with the public top-level modules target to compile both cores. PATH selects /usr/bin GCC 16.2.1 matching the headers, the compiler cache is bypassed, nice is +10, and compiler temporary files are in the scratch folder. A pristine tree, the Olo tree and the Olo-plus-RPM-Fusion tree were built separately. This is a source build. The stock prelinked packaging job has less work to do.

A livepatch can intercept an instrumented Linux-interface entry to reject a suspend *before calling RM* when a preflight policy applies. It cannot reach an uninstrumented inner HAL or safely unwind the NVKMS stack from nvkms_yield, a void function that only calls schedule. Altering the private Linux PM or DRM callbacks still needs compatible signatures and structure layouts, exact build-ID checks, a matching kernel, and ordinary livepatch consistency rules. Skipping releaseOwnership at one DRM call site also misses last-close and timer-driven console restoration. New struct fields, owning reference tokens, and a new ABI symbol between modules require a coherent rebuild. No livepatch was installed.
